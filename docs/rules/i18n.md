# Internationalization (i18n) Rules

**Context:** Translation requirements supporting Rule #4 in `CLAUDE.md`.

---

## What Needs Translation

### ✅ MUST be translated:

- All visible text in UI
- Button labels
- Headings and titles
- Messages and notifications
- Error messages
- Tooltips and help text
- Placeholders in inputs
- Alt text for images (when user-visible)
- ARIA labels (when user-visible)

### ❌ Does NOT need translation:

- HTML attributes: `class`, `type`, `role`
- CSS class names
- Code identifiers
- `data-testid` attributes
- Technical constants
- Variable/function names
- Comment text in code

---

## Translation File Structure

### Location:

```
src/i18n/locales/
├── en.json  # English translations (default)
└── de.json  # German translations
```

### Structure Pattern:

```json
{
  "app": {
    "title": "App level strings",
    "loading": "Generic UI elements"
  },
  "character": {
    "name": "Character properties",
    "tier": "More properties",
    "stats": {
      "might": "Nested for organization",
      "speed": "Group related translations"
    }
  },
  "errors": {
    "validation": "Error messages",
    "network": "Grouped by error type"
  },
  "buttons": {
    "save": "Common UI elements",
    "cancel": "Reusable across features"
  }
}
```

### Organization Guidelines:

- Group by feature/component
- Use nested objects for sub-categories
- Keep keys descriptive but concise
- Use dot notation for nesting
- Reuse common keys (buttons, errors, etc.)

## Usage Examples

### Basic Usage:

```typescript
import { html } from "lit-html";
import { t } from "@/i18n/index";

// ❌ BAD - Hardcoded text
html`<h1>Character Sheet</h1>
  <button>Save</button>
  <div>A tier ${tier}</div>`;

// ✅ GOOD - Using translation keys
html`<h1>${t("app.characterSheet")}</h1>
  <button>${t("buttons.save")}</button>
  <div>${t("character.sentence.prefix")} ${tier}</div>`;
```

### In Attributes:

```typescript
// ✅ GOOD - Translate ARIA labels, don't translate technical attributes
html`
  <button aria-label=${t("buttons.save.ariaLabel")}>${saveIcon}</button>

  <input type="text" placeholder=${t("character.name.placeholder")} />

  <div
    class="stat-pool"
    data-testid="might-pool"
    role="region"
    aria-label=${t("stats.might.label")}
  ></div>
`;
```

### Error Messages:

```typescript
import { t } from "@/i18n/index";

// ✅ GOOD
try {
  await saveCharacter(character);
} catch (error) {
  console.error("Save failed:", error);
  showNotification(t("errors.saveFailed"), "error");
}

// ❌ BAD
try {
  await saveCharacter(character);
} catch (error) {
  console.error("Save failed:", error);
  showNotification("Failed to save character", "error");
}
```

## Adding New Translations

1. **Add key to English file** (`src/i18n/locales/en.json`):

```json
{
  "character": {
    "stats": {
      "might": "Might",
      "newStat": "New Stat Name"
    }
  }
}
```

2. **Add corresponding German translation** (`src/i18n/locales/de.json`):

```json
{
  "character": {
    "stats": {
      "might": "Macht",
      "newStat": "Neuer Stat Name"
    }
  }
}
```

3. **Use in component**:

```typescript
html`<div>${t("character.stats.newStat")}</div>`;
```

4. `npm run check:i18n` (and the pre-commit hook) verify both keys exist
   before allowing a commit.

---

## Pre-Commit Hook Enforcement

`npm run check:i18n` scans all of `src/` for `t()` calls, extracts every key
used, and verifies each exists in **both** `en.json` and `de.json`, reporting
exactly which keys are missing from which file.

```
❌ Translation check failed!

Missing keys in en.json:
  - character.stats.newStat

Missing keys in de.json:
  - character.stats.newStat
  - buttons.export

Please add these keys before committing.
```

**Reference:** See `git.md`'s Troubleshooting section for what to do when the
hook blocks a commit generally.

## Interpolation

i18next supports interpolation:

```typescript
// Translation file
{
  "character": {
    "description": "A tier {{tier}} {{type}} who {{focus}}"
  }
}

// Usage
html`<div>
  ${t("character.description", {
    tier: character.tier,
    type: character.type,
    focus: character.focus,
  })}
</div>`;
```

## Troubleshooting

### "Key not found" warning in browser console

**Cause:** Using a translation key that doesn't exist.

**Solution:** check the key name for typos, verify the key exists in both
translation files, restart the dev server if needed.

### "Text still appears in English in German mode"

**Cause:** Hardcoded text instead of `t()`.

**Solution:** find the hardcoded text, add a translation key to both files,
replace the text with `${t("your.key")}`.

## Best Practices

### ✅ DO:

- Use descriptive key names
- Group related translations
- Keep translations consistent
- Test in both languages

### ❌ DON'T:

- Hardcode any user-visible text
- Use abbreviations in keys
- Skip either language file
- Bypass the pre-commit hook
- Translate technical identifiers
